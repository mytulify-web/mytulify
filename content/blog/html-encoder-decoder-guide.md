[HTML Encoder/Decoder](/developer-tools/html-encoder-decoder) is the tool for one job: encode and decode HTML entities in text. This guide covers the inputs to gather, one pass you can check, and the point where the result stops being enough.

## What to bring to the HTML Encoder/Decoder

Paste a real snippet, not a description of the snippet, unless the tool asks you to describe one.

HTML Encoder/Decoder runs in your browser. The file or the figures stay on your device.

## A worked pass with the HTML Encoder/Decoder

Encode and decode HTML entities in text. Feed it a small valid sample and a sample you know is broken. The valid one should succeed and the broken one should point at the problem.

Do that pass with a case you already understand. Then replace it with the real case. Changing one input at a time is how you see which field actually moved the result.

## How to check the result

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

## Where the HTML Encoder/Decoder stops

HTML Encoder/Decoder does not see your repository, your server, or the version of the library on your machine.

If your decision depends on a rule this page does not mention, a lender, a clinic, a teacher, a client, or the vendor of the file, use their rule. Keep this result as the draft you compare against that rule.

## Questions

### What does the HTML Encoder/Decoder do?

It is there to encode and decode HTML entities in text. The form on the [HTML Encoder/Decoder](/developer-tools/html-encoder-decoder) page is the place you do that.

### How do I know the HTML Encoder/Decoder result is usable?

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

### What should I not trust the HTML Encoder/Decoder to decide?

HTML Encoder/Decoder does not see your repository, your server, or the version of the library on your machine.
