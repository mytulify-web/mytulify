[Regex Tester](/developer-tools/regex-tester) is the tool for one job: test regular expressions against sample text with live match highlighting. This guide covers the inputs to gather, one pass you can check, and the point where the result stops being enough.

## What to bring to the Regex Tester

Paste a real snippet, not a description of the snippet, unless the tool asks you to describe one.

Regex Tester runs in your browser. The file or the figures stay on your device.

## A worked pass with the Regex Tester

The pattern is the expression. The sample is the text. A match highlight shows what the pattern actually caught, which is often wider than you meant because a dot matches almost anything.

Do that pass with a case you already understand. Then replace it with the real case. Changing one input at a time is how you see which field actually moved the result.

## How to check the result

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

## Where the Regex Tester stops

Regex Tester does not see your repository, your server, or the version of the library on your machine.

If your decision depends on a rule this page does not mention, a lender, a clinic, a teacher, a client, or the vendor of the file, use their rule. Keep this result as the draft you compare against that rule.

## Questions

### What does the Regex Tester do?

It is there to test regular expressions against sample text with live match highlighting. The form on the [Regex Tester](/developer-tools/regex-tester) page is the place you do that.

### How do I know the Regex Tester result is usable?

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

### What should I not trust the Regex Tester to decide?
