[JWT Decoder](/developer-tools/jwt-decoder) is the tool for one job: decode a JWT into its header, payload and signature. This guide covers the inputs to gather, one pass you can check, and the point where the result stops being enough.

## What to bring to the JWT Decoder

Paste a real snippet, not a description of the snippet, unless the tool asks you to describe one.

JWT Decoder runs in your browser. The file or the figures stay on your device.

## A worked pass with the JWT Decoder

A JWT is three Base64 parts: header, payload, and signature. Decoding shows the payload. It does not prove the signature is valid. Anyone can edit the payload of an undecoded token.

Do that pass with a case you already understand. Then replace it with the real case. Changing one input at a time is how you see which field actually moved the result.

## How to check the result

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

## Where the JWT Decoder stops

JWT Decoder does not see your repository, your server, or the version of the library on your machine.

If your decision depends on a rule this page does not mention, a lender, a clinic, a teacher, a client, or the vendor of the file, use their rule. Keep this result as the draft you compare against that rule.

## Questions

### What does the JWT Decoder do?

It is there to decode a JWT into its header, payload and signature. The form on the [JWT Decoder](/developer-tools/jwt-decoder) page is the place you do that.

### How do I know the JWT Decoder result is usable?

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

### What should I not trust the JWT Decoder to decide?
