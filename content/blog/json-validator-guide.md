[JSON Validator](/developer-tools/json-validator) is the tool for one job: validate JSON syntax and pinpoint errors. This guide covers the inputs to gather, one pass you can check, and the point where the result stops being enough.

## What to bring to the JSON Validator

Paste a real snippet, not a description of the snippet, unless the tool asks you to describe one.

JSON Validator runs in your browser. The file or the figures stay on your device.

## A worked pass with the JSON Validator

Validation tells you the first place the text stops being JSON. Fix that, then validate again. It does not check whether the keys match your API.

Do that pass with a case you already understand. Then replace it with the real case. Changing one input at a time is how you see which field actually moved the result.

## How to check the result

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

## Where the JSON Validator stops

JSON Validator does not see your repository, your server, or the version of the library on your machine.

If your decision depends on a rule this page does not mention, a lender, a clinic, a teacher, a client, or the vendor of the file, use their rule. Keep this result as the draft you compare against that rule.

## Questions

### What does the JSON Validator do?

It is there to validate JSON syntax and pinpoint errors. The form on the [JSON Validator](/developer-tools/json-validator) page is the place you do that.

### How do I know the JSON Validator result is usable?

Diff the output against the input for a formatter. For a generator, run the result in the real tool that will consume it.

### What should I not trust the JSON Validator to decide?

JSON Validator does not see your repository, your server, or the version of the library on your machine.
